> 版本 v0.1 ｜ 2026-08-18 ｜ 配套：docs/01-需求.md、AGENTS.md

## 1. 技术选型（定死，变更需改本文档并说明理由）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端框架 | **FastAPI**（Python 3.11+） | 自带 /docs 自动 API 文档；类型提示强制；async |
| 向量库 | **Chroma**（嵌入式） | MVP 零运维；metadata filter 支持权限过滤；接口抽象可换 Qdrant/ES |
| 关键词检索 | **rank_bm25**（Python 库） | 与向量召回做混合检索（RRF 融合） |
| Embedding | **Ollama + bge-m3**（本机） | 中文效果好、免费离线（已装） |
| Rerank | **bge-reranker-v2-m3**（Ollama，可选） | 接口预留，v1 可先关 |
| Chat LLM | **DeepSeek API**（OpenAI 兼容） | 用户现有 key |
| 业务数据库 | **SQLite**（文件型） | MVP 零运维；SQLAlchemy 抽象可换 PostgreSQL |
| 文件存储 | **本地目录**（data/files/） | 接口抽象可换 MinIO |
| 前端 | FastAPI 模板 + 极简 HTML/JS（MVP） | 功能优先，不建前端工程 |
| 部署 | Dockerfile + docker-compose.yml | 两容器：app + （预留） |

## 2. 架构图

### 2.1 逻辑视图（分层）

```
┌─ 接入层 ─────────────────────────────┐
│  routers/  auth · documents · chat · audit   （接请求、鉴权、参数校验）
├─ 业务层 ─────────────────────────────┤
│  services/ ingestion · retrieval · permission · audit
│  （业务规则全部在这层，routers 不许写业务逻辑）
├─ 能力层 ─────────────────────────────┤
│  storage/ vector_store(Chroma) · keyword_store(BM25)
│  llm/ embedding(Ollama) · chat(DeepSeek) · rerank(预留)
│  parser/ pdf · docx · xlsx · txt
├─ 存储层 ─────────────────────────────┤
│  SQLite(用户/文档/权限/审计) · Chroma(向量) · data/files(原件)
└──────────────────────────────────────┘
外部：Ollama(本机 11434) · DeepSeek API(出网)
```

### 2.2 部署视图

```
浏览器 → app 容器（FastAPI, :8000）
            ├── 本机 Ollama（host.docker.internal:11434，bge-m3）
            ├── DeepSeek API（api.deepseek.com，出网）
            └── 挂载卷 data/：files/ + chroma/ + app.db
```

## 4. 数据模型（SQLite）

```sql
users        (id, username, password_hash, department_id, clearance_level, role[employee|manager|boss])
departments  (id, name)
documents    (id, title, filename, uploader_id, clearance_level, status[parsing|ok|failed],
              fail_reason, created_at)
document_departments (document_id, department_id)   -- 多对多：跨部门文档
chunks       (id, document_id, chunk_index, content, chroma_id)
audit_logs   (id, user_id, action[upload|query|denied|perm_change], target, detail, created_at)
```

## 5. 核心数据流

### 5.1 入库（上传 → 可检索）

```
POST /documents（带部门+密级标签）
 → 存原件 data/files/ → 写 documents 表(status=parsing) → 审计
 → 解析（parser/）  失败 → status=failed+fail_reason，不进库
 → 切分（句边界+512 token 预算）
 → bge-m3 向量化 → 存 Chroma（metadata: {doc_id, dept_ids, clearance}）
 → status=ok
```

### 5.2 问答（权限过滤在检索层！）

```
POST /chat {question}
 → 鉴权取用户(部门,密级)
 → 混合检索：
     向量路：Chroma where={dept∈用户部门, clearance≤用户密级}  ← 权限过滤在此
     关键词路：BM25 后按同规则过滤（候选集来自权限内文档）
 → RRF 融合取 top-k → (可选 rerank)
 → 无命中 → 明确返回"未查到"
 → 拼 prompt（仅依据资料+引用编号）→ DeepSeek 生成
 → 答案+引用；写审计日志
```

## 6. 关键设计决策（面试答辩用）

1. **权限过滤前置到检索层**：Chroma metadata where 过滤，杜绝存在性泄露
2. **存储全部接口抽象**：vector_store/file_store 定义接口，Chroma/本地目录是 MVP 实现——生产可换 Qdrant/MinIO 不改业务代码
3. **失败文档零切片**：解析失败即终止，脏数据不进库
4. **RRF 融合而非加权**：名次融合对关键词/语义两类问题天然公平，免调权重
5. **审计先行**：upload/query/denied 全部留痕，越权尝试是安全事件
